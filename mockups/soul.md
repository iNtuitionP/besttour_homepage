# soul.md — 베스트투어 홈페이지 리디자인 시안 컨텍스트

이 문서는 YC design-with-AI 파이프라인(soul.md → 무드보드 → 원샷 N개 시안 → 비교 갤러리 → 선택 → 확장)의 `soul.md` 단계 산출물이다. 이후 홈 화면 시안 6개를 생성하는 모든 에이전트는 **이 파일 하나만**을 컨텍스트로 사용한다. 값(전화번호, 회사 정보, 팔레트 hex, 차량명, 요금표)은 반드시 원문 그대로 사용할 것 — 창작하거나 임의로 바꾸지 말 것. 유일하게 창작이 허용되는 부분은 "실시간 견적현황 더미 데이터"뿐이다.

---

## 1. 프로젝트 개요

- **회사**: 베스트투어 — 전세버스 대절 알선업체, 경기도 고양시 소재.
- **현황**: 노후화된 그누보드(Gnuboard) 기반 홈페이지(http://www.bestour.co.kr/)를 현대적으로 리디자인한다.
- **이번 단계 산출물**: 구현이 아니라 **클라이언트(사장님) 컨펌용 UIUX 시안**. 클릭 가능한 고충실도 정적 HTML이며 백엔드는 없다. 견적 위저드는 더미 요금표로 실시간 가격 계산이 실제 동작하는 프로토타입이어야 한다.
- **핵심 원칙 — 견적 최우선**: 방문자가 버스 대절 사이트에 오는 이유는 견적이다. 견적 기능을 홈 전면(히어로)에 배치한다. 연혁·인사말류는 전면에서 제외하되 삭제하지 않는다(서브페이지로 유지).
- **기존 기능/메뉴 100% 보존**: 삭제 없이 재배치만 한다.
- **보라색 아이덴티티 유지 + 모던화**: 실제 운행 버스가 보라색이며 "보라색버스"가 브랜드 자산이다. 촌스러운 보라 원색을 세련된 톤(딥퍼플/바이올렛 + 뉴트럴)으로 재해석한다.
- **참조 UX 패턴**: https://www.twdream.co.kr/ (견적 위저드 UX 패턴 참조)
- **저장 위치**: 저장소 `mockups/` 폴더. 홈 화면 시안 6개 + 핀 기능이 있는 비교 갤러리 페이지(`mockups/index.html`)를 만든다. 선택안 확정 후에는 견적 위저드 상세 + 서브페이지를 확장한다(이번 단계 범위 아님).

## 2. 견적 기능 정책 (스펙 §3 원문 — 사용자 확정)

- 위저드에서 **예상 가격을 실시간으로 표시**한다 (더미 요금표 기반).
- 사용자는 **예약을 걸 수 있다**. 온라인 결제는 하지 않는다.
- **예약 확정은 사장님이** 한다. 확정된 예약에 대해서만 결제가 진행된다 (오프라인/추후).
- 완료 화면 문구: "사장님 확정 후 연락드리며, 확정된 예약만 결제 진행됩니다."

## 5. 견적 위저드 플로우 — 7단계 (스펙 §6)

> **이번 시안 단계 범위**: 이번 6개 홈 시안에서는 위저드의 **히어로 진입점까지만** 구현한다(예: 차량 카드 클릭, 위젯 카드의 CTA 버튼). 위저드 내부 7단계 상세 화면 자체는 선택안 확정 후 별도 확장 단계에서 만든다. 아래 7단계는 히어로 진입점을 설계할 때 "이 버튼을 누르면 결국 무엇이 시작되는지"를 이해하기 위한 참고 정보로만 사용한다.

기존 견적요청 폼의 **모든 필드**를 수용한다:

1. **차량 선택** — 45인승 관광버스 / 35인승 관광버스 / 28인승 우등리무진 / 25인승 관광버스 / 16인승 관광버스 (카드 UI)
2. **여행 정보** — 여행구분(가족여행/관혼상제/워크샵/친목회/종교단체/공항픽업/대학MT/현장학습/외국인의전.관광/기타), 출발지/도착지(서울~제주 16개 시도), 경유지(선택), 운행구분(왕복/편도/편도·편도)
3. **날짜·시간** — 출발일시, 상행일시 (캘린더 + 시간 선택)
4. **대수·인원** — 차량 대수, 예상 인원
5. **예상 가격 실시간 표시** — 더미 요금표 기반 계산 결과
6. **연락처 + 추가 옵션** — 성명, 핸드폰, (전화번호/팩스/이메일 선택), 견적확인방법(핸드폰/전화/팩스/이메일), 계산방법(현금/카드/세금계산서발행), 주차료 포함 여부, VAT 10% 포함 여부, 남기고 싶은 말씀, 답변메일받기 → CTA "예약 걸기"
7. **완료 화면** — 접수 확인 + 사장님 확정/결제 안내

## 6. 디자인 소울 — 7개 원리 (전문)

(사용자 제공 레퍼런스 4종에서 추출 — 겉모습 복제 금지, 원리만 적용)

1. **견적 진입은 히어로 속 컴팩트 위젯 카드** — 거대한 폼을 페이지 하단에 두지 않고, 밀도 있는 카드 하나가 히어로에 떠 있다 (레퍼런스: Shuttle의 오버랩 폼 카드, Premier Limo의 우측 부킹 위젯)
2. **한 색 계열에 대한 확신** — 브랜드색을 여러 틴트로 깊게 쓰고(면·배경·일러스트까지), 포인트로만 뿌리지 않는다 (레퍼런스: Global Express의 블루 몰입)
3. **타이포 대비** — 큰 볼드 헤드라인 + 문장 속 핵심 단어만 액센트 컬러/서체 변화 (레퍼런스: Shuttle의 컬러 키워드, Punctual의 손글씨+헤비산스 믹스)
4. **신뢰는 숫자로** — 연혁 문단 대신 스탯 블록(운행 연차, 누적 견적 건수)과 실시간 견적현황 (레퍼런스: Shuttle의 25 years/2,640 customers)
5. **가격 투명성 전면** — 차량/노선 카드에 예상가 노출 (레퍼런스: Global Express의 목적지 카드 가격, Premier Limo의 시간당 요금)
6. **섹션 리듬** — 라이트/다크 교차, 번호 매긴 에디토리얼 구조(01/02/03), 넉넉한 여백 (레퍼런스: Premier Limo)
7. **사진은 드라마틱하게** — 오버레이, 프레임 브레이크, 풀블리드. 보라색 버스 실사진이 최고의 자산 (레퍼런스: Punctual의 폰 프레임을 뚫는 버스)

## 10. 2026-08-08 방향 확정 (시안 1~6 피드백 반영 — 이 섹션이 기존 내용과 충돌하면 이 섹션이 우선)

### 10.1 확정 디자인 방향
- **시안 1(variant-01-deep-purple)의 레이아웃 구조 × 시안 5(variant-05-card-grid)의 색감**을 통합.
- 톤: 고객층(단체 총무, 중장년)이 보수적이므로 최신 트렌드 과시 대신 **"오래 운영해온 신뢰 있는 회사"** 느낌. 라이트 라벤더/화이트 지면, 안정적 그리드, 과한 글래스모피즘·화려한 마이크로 인터랙션 배제. 신뢰 신호(운영 연차, 정식 등록업체, 보험 내용, 실적 숫자)를 전면 배치.

### 10.2 주력 서비스 서사 — 공항 노선
- 주력 상품은 **공항 송영**. (내부 참고: 외국인 투어 전문이라 공항에서 투어 고객을 태우고 나가는 구조 → 공항 노선은 가격 경쟁력이 있음.) **단, 이 사업 구조는 대외 카피에 절대 노출하지 않는다** — "나가는 버스에 모시니까", "태우고 나가는" 등 원가 구조를 드러내는 표현 금지. 카피는 혜택(더 저렴함)만 말하고, 이유는 "공항 노선 전문 / 상시 운행 노하우" 수준으로만 설명한다.
- "송영" 단독 사용 금지 — 생소함. **확정 표기: "공항 픽업·샌딩 (송영 전문)"** — 메인 카피/메뉴에는 "공항 픽업·샌딩"을 쓰고 괄호로 "(송영 전문)"을 병기한다.
- 서사 예시 카피 (BM 비노출 버전): "인천공항 갈 때, 올 때 — 공항 노선, 자신 있게 저렴합니다", "공항 노선을 매일 운행하는 전문 업체의 가격", "외국인 관광 전문 노하우 그대로".
- 홈 견적 위젯에도 **경유지 추가**(선택, 컴팩트) 기능이 있어야 한다 — 위저드뿐 아니라 홈에서 바로 견적을 볼 때도 경유지를 넣을 수 있어야 함.

### 10.3 히어로 = 5초 자동 캐러셀
- 5초마다 슬라이드 전환(수동 화살표/인디케이터, hover 일시정지, prefers-reduced-motion 존중):
  1. 인천공항 픽업 — 가격 경쟁력 서사
  2. "전국 어디서나 갑니다" — 16개 시도 운행
  3. 외국인 투어 전문 · 신뢰 스토리 (보험/정식 등록/연차)
- **견적 위젯은 시안 1처럼 히어로 우측 고정** — 캐러셀과 독립적으로 항상 노출.

### 10.4 예약 플로우 확장
- 예상가 확인은 무기명 유지. **"예약 걸기" 버튼을 누르면 이름 + 전화번호 입력 단계**가 나온다.

- **경유지는 여러 개 추가 가능**: 위저드 여행 정보 단계에서 [+ 경유지 추가] 버튼으로 경유지를 0개~여러 개 추가/삭제할 수 있다. 추가된 경유지는 최종 요약과 문자 미리보기에 "출발지 → 경유1 → 경유2 → 도착지" 형태로 반영.
