## 1. 오픈에 필요한데 계획에 없는 것

1. **계정·요금제 조달 태스크가 0개다.** A1(Upstash·Turnstile), C1(Solapi), D5(Storage), E4(Vercel Cron), §13.9의 Supabase Pro $25가 전부 외부 계정에 의존하는데, 누가 어느 명의(이승묵)로 언제 가입하고 결제수단을 누가 등록하며 env를 누가 발급하는지가 어느 Phase에도 없다. → 고침: Phase 0에 `P0-6 계정·요금제 조달 + env 발급`을 신설하고 A1·C1·D5·E4의 선행 의존으로 건다.
2. **Solapi 발신번호 사전등록(전기통신사업법)이 태스크가 아니다.** 서류·심사 리드타임이 수일이고, `.env.example`의 `SMS_SENDER=15666188`(대표번호 1566)로 SMS 발신이 가능한지 자체가 미검증이다. → 고침: `P0-7 발신번호 등록 착수`를 지금 시작하고, C Phase 게이트를 "등록 완료"에 명시적으로 의존시킨다.
3. **환경 분리 설계가 없다.** A/B/D 게이트가 전부 "프리뷰에서 E2E"인데 프리뷰가 어느 DB를 쓰는지 미정 → 프리뷰 테스트가 운영 DB에 실개인정보 행을 쓴다. → 고침: `local / preview(별도 Supabase 프로젝트, noindex) / prod` 3분리를 Phase 0 태스크로 추가.
4. **개인정보 처리방침 필수기재 6종이 L2 테스트 목록에 없다** — 권리행사 방법·절차, 파기 절차·방법, 안전성 확보조치, 자동수집장치(B6의 "오늘 하루 보지 않기" localStorage가 여기 해당), 권익침해 구제방법, 처리방침 변경 고지. 추가로 **A4 접수현황 공개(마스킹 성명 노출)를 고지하는 항목이 없다.** → 고침: L2 필수 섹션 목록을 이 7항목까지 확장하고 테스트를 그 목록에서 파생시킨다.
5. **이용약관의 실체 항목이 정의되지 않았다** — 계약 성립 시기, 청약철회 기한·행사방법·효과(§13②5호), 면책, 준거법·관할, 분쟁조정 기관. L2는 취소·환불 4단계만 본다. → 고침: L2에 terms 필수 섹션 목록을 조문 번호와 함께 명문화.
6. **그누보드 백업(메모 P0 #3)이 Phase F 체크리스트로 밀려 있다.** 카페24 자동백업 보관은 7일이라 지금 안 받으면 복구 불가다. → 고침: 백업을 Phase 0의 사장님 액션 태스크로 승격하고 증적(파일 목록·보관 위치)을 레저에 기록.
7. **에러 경로·모니터링이 없다** — 404/500/error boundary, 발송 실패 알림 채널, 에러 트래킹. D6 대시보드는 사장님이 열어야만 보인다. → 고침: B에 not-found/error 라우트, C에 발송 실패 시 기존 `bestour2013@naver.com`으로 폴백 통지 추가.
8. **운영 인계물이 없다** — admin 사용 매뉴얼, 계정 발급·비밀번호 정책, 장애 시 연락 절차. → 고침: Phase D에 `D7 운영 인계 문서 + 사장님 실사용 리허설`을 추가.
9. **일정 추정이 0이다.** 도메인 만료 D-29인데 어느 Phase가 며칠인지 없다. → 고침: Phase별 소요일 추정 + 만료일 역산표를 §3 머리에 붙인다.
10. **`mockups/soul.md:84`와 `plans/2026-08-07-...:78`(4,800의 발원지) 수정, CLAUDE.md §3의 "실증 불가 수치 금지"·"면허→등록" 전역 정정이 어느 태스크에도 없다.** → 고침: soul.md 수정을 §6.3 UIUX 요청 목록에, CLAUDE.md 개정을 Phase 0 태스크로 등록.
11. 구 사이트 개인정보(게시판·회원·백업본)의 **파기 시점·범위**가 없다. 이관 안 한다는 결정만 있고 원본 처분 계획이 없다. → 고침: E3에 "구 사이트 개인정보 파기 + 백업본 보관기한" 항목 추가.

## 2. 중간에 막히는 지점

1. **마이그레이션 번호 역전.** L1이 `0002`를 만드는데 그 선행인 P0-5가 `0003`을 만든다. 원격에 0003을 push한 뒤 0002를 추가하면 Supabase CLI의 이력이 out-of-order가 되어 적용이 깨진다. → 고침: 생성 순서대로 파일명을 부여(0002=places, 0003=consent)하거나 타임스탬프 네이밍으로 전환.
2. **L1의 검증("동의 없는 insert가 실패")이 L1 자신의 설계(NOT NULL은 0002b로 연기)와 모순**이다. 지금은 nullable이라 실패시킬 수 없다. → 고침: 0002에서 바로 `check (privacy_consent_at is not null)`을 걸거나, 검증 문구를 "코드 경로 차단"으로 정정하고 0002b를 A2와 같은 태스크에 묶는다.
3. **Phase L의 독립성 주장이 성립하지 않는다.** L3이 "B1의 라우팅 골격 일부 선취"에 의존한다고 스스로 적었다. 더 나쁜 것은 기존 `app/layout.tsx`를 둔 채 `app/[locale]/layout.tsx`를 추가하면 root layout이 중첩되고 `/admin`(로케일 밖)이 구조적으로 충돌한다. → 고침: 라우트 그룹 `(site)/[locale]` + `(admin)/admin` 골격을 `P0-0`으로 앞당겨 L의 선행으로 못박는다.
4. **L4 LegalFooter가 곧 사이트 푸터**인데 목업 확정 전에 만들고 B1이 재사용한다 → UIUX가 푸터를 바꾸면 L4·B1 동시 재작업. → 고침: "법정 데이터·문구 블록"과 "레이아웃 푸터"를 분리해 L에서는 전자만 만든다.
5. **A1 fail-closed 정책 + A2/B4 게이트가 실키를 요구**한다. 키 조달 태스크가 없으므로 Phase A 게이트를 통과할 방법이 없다. → 고침: 조달 태스크를 선행으로 걸고, 그 전까지는 Cloudflare 공식 테스트 키로만 진행한다고 브리프에 명시.
6. **C 게이트("실기기 수신 확인")가 미회신 항목에 직접 의존**하는데 §7 표는 같은 항목을 "차단 안 함"으로 분류했다 — 계획 내부 모순. → 고침: C 게이트를 "mock 경로 통과"와 "실발송 스모크"로 분리하고 후자만 발신번호 등록에 의존시킨다.
7. **E3(레거시 공지·갤러리 적재)은 카페24 FTP/DB 접근이 필요**한데, §7은 카페24 로그인을 "F만 차단"으로 분류했다. → 고침: 로그인 의존 태스크에 E3와 백업을 함께 표기.
8. **D5는 현재 설계로 실행 불가능하다.** `sharp`가 의존성에 없고, sharp 기본 빌드는 libheif가 없어 HEIC를 디코드하지 못한다. 20MB×30장을 Server Action으로 올리면 Next 기본 `bodySizeLimit` 1MB와 Vercel 요청 4.5MB에 먼저 걸린다. → 고침: "브라우저 → signed URL 직업로드(원본 버킷) → 서버는 변환만"으로 재설계하고 HEIC는 클라이언트 변환 또는 미지원으로 확정.
9. **드리프트 베이스라인 갱신을 컨트롤러 단독으로 묶어 직렬 병목**이 되고, `mockups/soul.md`는 UIUX 소유인데 실증 수치 수정 책임은 구현 측 게이트에 있어 소유권이 교착한다. → 고침: 베이스라인 갱신을 UIUX 커밋 후처리 스크립트로 이관하고, soul.md 수정은 §6.3 요청 항목으로 명시.
10. **`public/brand/` ↔ `mockups/assets/brand/` "수동 동시 반영"에 어긋남 검출 장치가 없다.** → 고침: `check-mockup-drift.sh`에 두 디렉터리 해시 비교를 추가.
11. **Phase B 완료 상태가 위험하다.** "방문자 접수 가능"인데 admin·문자·파기 배치가 전부 없어 개인정보만 쌓이고 아무도 못 본다. → 고침: B 산출물은 프리뷰 한정으로 못박고 공개 배포 게이트를 C+D+E4 이후로 명시.

## 4. 서브에이전트가 브리프만 보고 못 끝낼 태스크

- **L2(법정 문서 본문)** — 지급수단·시기, 보유기간 근거, 신고 실체, Supabase 리전이 전부 미확정이고 법 해석이 필요하다. 브리프만 주면 반드시 창작한다(창작 금지 규약 정면 위반). → 고침: 컨트롤러가 문안을 확정해 "삽입할 텍스트 전문"으로 브리프에 싣고, 서브에이전트에겐 배선·테스트만 맡긴다.
- **D1(인증 게이트)** — Supabase Auth 대시보드 설정(계정 생성, 이메일 provider·SMTP, 비밀번호 정책)은 코드 밖이고, 계획에 admin 계정 발급 절차 자체가 없다. → 고침: 인간 액션 체크리스트를 D1 브리프에 첨부하고 코드 범위를 `requireAdmin()`+정책까지로 한정.
- **D5(갤러리)** — §2-8의 아키텍처 재설계 판단 + 버킷·정책 생성(콘솔)이 필요. → 고침: 재설계를 컨트롤러가 확정한 뒤 착수.
- **B2(KrMap)** — 16개 라벨 정책이 미결정이라 "무엇이 완성인지"가 브리프에 없다. → 고침: UIUX 결정 수령 전에는 카드 리스트만 구현하고 지도 라벨은 보류.
- **C1·C2·C4** — 계정·발신번호·실기기·포털 도달률 실측이 필요. → 고침: 코드 태스크(mock)와 인간 스모크 태스크를 분리 발행.
- **E1(리다이렉트)** — 12개 URL의 목적지는 사업 판단이다. → 고침: 목적지 표를 확정값으로 브리프에 싣는다.
- **F1·F2** — DNS 콘솔·사장님 계정 작업. → 고침: 서브에이전트 산출물은 런북과 `verify-cert.sh`까지로 한정.
- **E5(Lighthouse 90+)** — 측정 URL·스로틀링·회차·중앙값 기준이 없어 완료 판정이 불가능. → 고침: 측정 프로토콜을 브리프에 고정.
- **P0-2(semantic 토큰 네이밍)** — 목업 섹션 구조에 대한 설계 판단이다. → 고침: 토큰 이름 목록을 컨트롤러가 먼저 확정.

## 5. 검증이 형식적이기만 한 태스크

- **L2·L5** — "필수 섹션 존재" grep은 법적 충분성을 전혀 보증하지 않는다. → 고침: 조문↔문구↔화면 위치 매핑표를 만들고 사람 리뷰 서명을 게이트에 추가.
- **P0-3(verbatim 바이트 일치)** — 파일 존재만 본다. 화면 렌더·위치는 미검증. → 고침: 렌더 테스트 + browse 스크린샷 대조를 필수화.
- **A1** — RL·Turnstile이 전량 mock이라 실키 동작이 오픈까지 한 번도 검증되지 않는다. → 고침: 프리뷰 실키 스모크(연속 요청 429, 위조 토큰 거부) 1회를 게이트에 추가.
- **P0-5** — "16행"만 센다. 16쌍·가격 실값·highlight가 스펙 §13.2와 일치하는지는 미검증. → 고침: 스펙 값 배열을 픽스처로 박고 전량 비교.
- **A4** — "60초 캐시" 검증 방법이 없고 마스킹 누출 검사도 없다. → 고침: 응답에 원문 이름·전화가 포함되지 않는지 property test.
- **E4** — "드라이런 성공"은 경계 시각(KST/UTC), 확정 5년/미확정 1년 분기, 삭제 상한을 증명하지 않는다. → 고침: 고정 시각 주입으로 경계 케이스 테스트.
- **D2** — "감사 로그에 기록"만 본다. 역방향 거부와 동시 클릭 경합이 미검증. → 고침: 동시 update 경합 테스트를 추가.
- **B3** — "목업 대조 스크린샷 동일"에 허용 오차·도구가 없어 주관 판정이다. → 고침: 비교 도구와 픽셀 오차 임계값을 명시.
- **E2** — robots/sitemap 존재 확인은 형식. → 고침: sitemap URL 목록이 실제 라우트 목록과 1:1인지 테스트.
- **C3** — "광고 문구 0건 grep"에 금지어 목록이 없다. → 고침: 광고 판별 금지어 목록을 파일로 고정하고 KO·EN 양쪽에 적용.
- **전반** — "375px 가로 스크롤 0 · 콘솔 에러 0"만으로 UI 완료를 판정한다. 상태 전이·검증 에러 표시·재시도 경로가 빠진다. → 고침: UI 태스크마다 "실패 경로 1건"을 검증 항목으로 의무화.
